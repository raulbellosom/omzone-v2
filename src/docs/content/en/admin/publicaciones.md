# Publications

A **publication** is the editorial layer of an experience — the story, the photos, the descriptions, and all the content that clients read on the public site.

Publications are intentionally separate from the commercial setup (pricing, schedules). This lets you update the storytelling without touching the business logic, and vice versa.

---

## Creating a publication

1. Go to **Publications** in the sidebar.
2. Click **New publication**.
3. Fill in the basics:
   - **Title** — The public-facing title.
   - **Summary** — A short teaser (2-3 lines) that appears in listings.
   - **Cover image** — The main photo clients see first.
   - **Experience** — Link this publication to the experience it represents.
4. Save.

---

## Building the content

Once the publication is created, you build its content using **sections and blocks**. Each section is a content area (hero image, text block, gallery, about the instructor, etc.).

See **Sections & Blocks** for details on how to structure a publication.

---

## Publication status

| Status    | What it means                                             |
| --------- | --------------------------------------------------------- |
| Draft     | Only visible to admins — not on the public site           |
| Active    | Live on the public site                                   |
| Scheduled | Will go live at a specific date/time                      |
| Archived  | No longer active — kept for reference                     |

---

## Updating a publication

You can edit a publication at any time. Changes go live immediately (if the publication is active), so be deliberate about edits you make while a session is actively booking.

---

## Publications vs. experiences

| Publications                               | Experiences                                 |
| ------------------------------------------ | ------------------------------------------- |
| Tell the story — who, why, what to expect  | Define the product — price, dates, capacity |
| Photos, narratives, instructor bios        | Sale mode, schedule, add-ons                |
| Can exist standalone (blog-style articles) | Can exist without a publication             |
| Multiple publications can link to one experience | One experience links to one active pub  |

---

## SEO and discoverability

Publications support:
- **Page title** and **meta description** — for search engine results
- **Canonical URL** — to avoid duplicate content issues
- Structured data is generated automatically for linked experiences

Keep titles and descriptions unique across all publications for best search performance.
